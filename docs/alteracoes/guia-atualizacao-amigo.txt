2. CORRECOES TECNICAS RECOMENDADAS PARA O SEU REPOSITORIO
--------------------------------------------------------------------------------

[MELHORIA 1] Correcao do F5 no Login do Painel Admin (/admin)
--------------------------------------------------------------------------------
Problema: Ao digitar usuario/senha corretos no /admin, o painel as vezes ficava
na mesma tela sem redirecionar, exigindo dar F5 para entrar no /admin/content.
Arquivos alterados:
- src/app/features/admin/authentication/admin-authentication.ts
- src/app/features/admin/authentication/admin-authentication.spec.ts
- src/app/core/auth/admin-auth.models.ts

Como aplicar:
No componente AdminAuthentication, adicionamos a escuta reativa da sessao
logo no inicio do ciclo de vida: se a sessao estiver autenticada ou for resolvida
com sucesso logo apos o submit, o roteador navega imediatamente para a rota
pos-login sem depender de reload de pagina.


[MELHORIA 2] Suporte a SUPABASE_PUBLISHABLE_KEY no generate-runtime-config
--------------------------------------------------------------------------------
Problema: O Supabase atualizou o formato padrao de chaves nos dashboards recentes
para "sb_publishable_...", renomeando a variavel no .env para SUPABASE_PUBLISHABLE_KEY.
Arquivo alterado:
- scripts/generate-runtime-config.mjs

Como aplicar:
Alterar a leitura para:
const publishableKey = process.env.SUPABASE_PUBLISHABLE_KEY ?? process.env.SUPABASE_ANON_KEY ?? '';
Isso garante compatibilidade com qualquer uma das duas nomenclaturas.


[MELHORIA 3] Conectar o Site Publico a Publicacao Editorial (Adapter)
--------------------------------------------------------------------------------
Problema: O site publico (/) exibia apenas os dados estaticos locais em vez de
consumir o conteudo publicado pelo editor visual via Supabase.
Arquivos criados/alterados:
- src/app/features/portfolio/content/editorial-snapshot-adapter.ts (NOVO)
- src/app/features/portfolio/content/editorial-snapshot-adapter.spec.ts (NOVO)
- src/app/features/portfolio/content/portfolio-content.service.ts

Como aplicar:
O EditorialSnapshotAdapter converte a publicacao vinda da RPC
get_versioned_public_portfolio para a interface PortfolioContent.
O servico PortfolioContentService agora tenta carregar a versao publicada do
Supabase e, se estiver offline ou sem configuracao, faz fallback transparente
para os dados estaticos locais.

[MELHORIA 5] Configuracao do Storage no Supabase para Upload de Curriculos
--------------------------------------------------------------------------------
Caso encontre erro 400 (Bucket not found) ao tentar subir PDFs no painel /admin/media:
Certifique-se de que o bucket 'curricula' existe no Supabase Storage:
- Bucket ID: 'curricula' (public = true, file_size_limit = 52428800, mime = 'application/pdf')
- Politicas RLS em storage.objects para permitirem insert/update/delete apenas por usuarios
  que existam na tabela public.portfolio_admins.
- Criar a RPC replace_portfolio_curriculum para atualizacao atomica no banco e troca de arquivo.


[MELHORIA 6] Padronizacao Arquitetural do Frontend, Nomenclatura Canonica Angular e Migracao SCSS -> CSS
--------------------------------------------------------------------------------
Problema/Objetivo:
O projeto possuia algumas inconsistencias estruturais em relacao aos padroes
empresariais e ao Angular Style Guide oficial:
1. Arquivos de estilos estavam como .scss, porem o codigo utilizava 100% CSS nativo
   (custom properties / variaveis CSS), gerando sobrecarga desnecessaria de build
   no Angular CLI e confusao sobre uso de pre-processador.
2. Nomenclatura dos arquivos e classes estava encurtada (ex: app.ts em vez de
   app.component.ts; admin-workspace.ts em vez de admin-workspace.component.ts).
3. Componentes como AdminWorkspace e EditorialProjectDetail possuiam templates e
   estilos inline extensos misturados no proprio arquivo TypeScript.
4. O componente ProjectTechnologies estava acoplado internamente na feature portfolio,
   embora seja um componente de apresentacao puro reutilizavel.
5. As pastas de features misturavam paginas e servicos sem divisao clara de camadas.

Arquivos configurados e alterados:
- angular.json: configurado "schematics": { "@schematics/angular:component": { "style": "css" } }
  e "inlineStyleLanguage": "css" tanto em "build" quanto em "test".
- src/styles.scss -> renomeado para src/styles.css (e atualizado no angular.json).
- Todos os arquivos *.component.scss renomeados para *.component.css, com
  styleUrls atualizados em todos os decoradores @Component.
- Padronizacao canonica de sufixos Angular:
  * src/app/app.ts -> src/app/app.component.ts (classe AppComponent)
  * admin-authentication.ts -> admin-authentication.component.ts
  * admin-workspace.ts -> admin-workspace.component.ts
  * content-management.ts -> content-management.component.ts
  * media-management.ts -> media-management.component.ts
  * visual-editor.ts -> visual-editor.component.ts
  * editorial-project-detail.ts -> editorial-project-detail.component.ts
  * portfolio-page.ts -> portfolio-page.component.ts
  * project-detail.ts -> project-detail.component.ts
- Desacoplamento de templates e estilos:
  * AdminWorkspace agora possui admin-workspace.component.html e admin-workspace.component.css
  * EditorialProjectDetail agora possui editorial-project-detail.component.html e editorial-project-detail.component.css
- Nova camada Compartilhada (Shared Layer):
  * Criado src/app/shared/components/project-technologies/ com seu .ts, .html e .css.
- Organizacao modular por feature (Inspirada no Angular Style Guide e projetos modulares):
  * src/app/features/portfolio/pages/ (portfolio-page, project-detail)
  * src/app/features/portfolio/services/ (portfolio-content, adapters, validadores)
  * src/app/features/admin/pages/ (authentication, workspace, content, media, editor, detail)
  * src/app/features/admin/services/ (servicos e models de rascunho, midia, etc.)
  * src/app/features/admin/directives/ (diretivas editoriais estruturadas)

Como aplicar no seu repositorio (Passo a Passo sem perder seus dados):
1. Copie as alteracoes do angular.json (troca de "scss" para "css").
2. Se voce mantiver os mesmos componentes, renomeie os estilos para .css e atualize os
   decorators @Component({ styleUrls: ['./nome.component.css'] }).
3. Para adotar a divisao de pastas:
   - Mova os servicos para a subpasta services/ de cada feature.
   - Mova as telas para pages/.
   - Atualize os caminhos de importacao (imports no TypeScript).
4. ATENCAO AOS SEUS DADOS:
   - Se for fazer git merge ou git cherry-pick, garanta que o seu arquivo de
     conteudo pessoal (portfolio-content.ts e portfolio-translations.ts) seja mantido
     com os seus textos e projetos! Se os arquivos forem movidos para services/,
     basta colocar o seu conteudo dentro de src/app/features/portfolio/services/portfolio-content.ts.
5. Rodar validacao:
   Execute `npm test -- --watch=false` para garantir que todos os testes passem
   e `npm run build` para validar a compilacao.

[DICA DE COMPILACAO] Modificador 'override' no PublishedSnapshotContentService
--------------------------------------------------------------------------------
No arquivo src/app/features/portfolio/services/published-snapshot-content.service.ts
linha 46, o metodo "async listSectionOrder()" sobrescreve o metodo da classe base.
Para evitar o erro TS4114 quando a flag "noImplicitOverride" estiver ativada,
adicione a palavra-chave "override":
  override async listSectionOrder(): Promise<string[]> { ... }
