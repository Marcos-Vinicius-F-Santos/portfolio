2. CORRECOES E MELHORIAS TECNICAS IMPLEMENTADAS
--------------------------------------------------------------------------------

[MELHORIA 1] Correcao do F5 no Login do Painel Admin (/admin)
--------------------------------------------------------------------------------
Problema: Ao digitar usuario/senha corretos no /admin, o painel as vezes ficava
na mesma tela sem redirecionar, exigindo dar F5 para entrar no /admin/content.
Arquivos alterados:
- src/app/features/admin/authentication/admin-authentication.ts
- src/app/features/admin/authentication/admin-authentication.spec.ts
- src/app/core/auth/admin-auth.models.ts

Como aplicar:
No componente AdminAuthentication, adicionamos a escuta reativa da sessao
logo no inicio do ciclo de vida: se a sessao estiver autenticada ou for resolvida
com sucesso logo apos o submit, o roteador navega imediatamente para a rota
pos-login sem depender de reload de pagina.


[MELHORIA 2] Suporte a SUPABASE_PUBLISHABLE_KEY no generate-runtime-config
--------------------------------------------------------------------------------
Problema: O Supabase atualizou o formato padrao de chaves nos dashboards recentes
para "sb_publishable_...", renomeando a variavel no .env para SUPABASE_PUBLISHABLE_KEY.
Arquivo alterado:
- scripts/generate-runtime-config.mjs

Como aplicar:
Alterar a leitura para:
const publishableKey = process.env.SUPABASE_PUBLISHABLE_KEY ?? process.env.SUPABASE_ANON_KEY ?? '';
Isso garante compatibilidade com qualquer uma das duas nomenclaturas.


[MELHORIA 3] Conectar o Site Publico a Publicacao Editorial (Adapter)
--------------------------------------------------------------------------------
Problema: O site publico (/) exibia apenas os dados estaticos locais em vez de
consumir o conteudo publicado pelo editor visual via Supabase.
Arquivos criados/alterados:
- src/app/features/portfolio/content/editorial-snapshot-adapter.ts
- src/app/features/portfolio/content/editorial-snapshot-adapter.spec.ts
- src/app/features/portfolio/content/portfolio-content.service.ts

Como aplicar:
O EditorialSnapshotAdapter converte a publicacao vinda da RPC
get_versioned_public_portfolio para a interface PortfolioContent.
O servico PortfolioContentService agora tenta carregar a versao publicada do
Supabase e, se estiver offline ou sem configuracao, faz fallback transparente
para os dados estaticos locais neutros.


[MELHORIA 4] Limpeza e Otimizacao dos Testes Unitarios
--------------------------------------------------------------------------------
- Testes redundantes e triviais foram eliminados.
- Testes com assercoes literais de nomes de desenvolvedores foram desacoplados,
  garantindo que mudancas de dados no banco nao quebrem a suite de testes.
- Resultado: 33 arquivos de spec, 154 testes passando com 100% de sucesso (~3.8s).


[MELHORIA 5] Configuracao do Storage no Supabase para Upload de Curriculos
--------------------------------------------------------------------------------
Caso encontre erro 400 (Bucket not found) ao tentar subir PDFs no painel /admin/media:
Certifique-se de que o bucket 'curricula' existe no Supabase Storage:
- Bucket ID: 'curricula' (public = true, file_size_limit = 52428800, mime = 'application/pdf')
- Politicas RLS em storage.objects para permitirem insert/update/delete apenas por usuarios
  que existam na tabela public.portfolio_admins.
- Criar a RPC replace_portfolio_curriculum para atualizacao atomica no banco e troca de arquivo.


[MELHORIA 6] Padronizacao Arquitetural do Frontend e Migracao SCSS -> CSS (DECISAO-013)
--------------------------------------------------------------------------------
- 100% CSS nativo sem dependencia de compilador Sass.
- Nomenclatura canonica Angular: *.component.ts, *.component.html, *.component.css.
- Componentes reutilizaveis desacoplados em src/app/shared/components/.


[MELHORIA 7] DECISAO-015: Destinos Dinamicos de Contato, Modularizacao e Performance
--------------------------------------------------------------------------------
1. Painel de Contato Dinamico (WhatsApp e E-mail):
   - Os destinos de WhatsApp e e-mail nao estao mais chumbados no TypeScript.
   - Sao extraidos dinamicamente em tempo de execucao a partir dos dados de
     contato ('phone' e 'email') cadastrados no snapshot do Supabase.
2. Reorganizacao de Pastas Compartilhadas:
   - Os componentes de apresentacao foram movidos para src/app/shared/components/:
     * contact-panel/
     * admin-card/
     * admin-feedback/
     * admin-page-header/
     * admin-section-header/
   - Pastas legadas 'presentation/' e 'ui/' foram removidas.
3. Lazy Loading Universal e Otimizacao de Performance:
   - Rotas modularizadas em app.routes.ts, portfolio.routes.ts e admin.routes.ts.
   - Reducao do pacote inicial de 603 kB para 469.13 kB (abaixo do teto de 500 kB).
   - Compilacao limpa com `npm run build` sem nenhum warning de budget.
